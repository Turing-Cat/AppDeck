# 指定应用窗口切换方案

Status: resolved

本方案已获用户确认，并完成实施。

## 1. 目标与范围

在现有 B 方案的右侧窗口列表中，支持鼠标点击和键盘选择。用户可以在同一应用的多个 App Window 之间选择目标，包括位于不同工作区（虚拟桌面）的窗口。选择对象是窗口；工作区用于说明窗口的位置。

聚焦目标窗口时，由现有 Hyprland 窗口聚焦操作处理工作区切换。实施时需要在真实桌面验证跨工作区与跨显示器的行为，不单独添加「先切换工作区」命令。

本次保留应用列表排序、搜索、启动和应用级 Close／Kill 的范围。窗口截图、工作区分组、单窗口 Close／Kill 不在本次范围内。

## 2. 交互规则

「应用选择状态」表示尚未通过 Tab 明确选择窗口；「窗口选择状态」表示已经通过 Tab 指定了右侧窗口。这两个状态是逻辑选择状态，不要求移动真实键盘输入焦点。

| 操作 | 应用选择状态 | 窗口选择状态 |
| --- | --- | --- |
| `↑`／`↓` | 切换左侧应用 | 切换左侧应用，并回到应用选择状态 |
| `Page Up`／`Page Down`、`Home`／`End` | 按原规则选择应用 | 按原规则选择应用，并回到应用选择状态 |
| `Tab` | 进入窗口选择，选中最近使用的窗口 | 选择列表中的下一个窗口，末尾循环到首项 |
| `Shift + Tab` | 进入窗口选择，选中最近使用的窗口 | 选择列表中的上一个窗口，首项循环到末尾 |
| `Enter` 或 Focus 按钮 | 聚焦所选应用最近使用的窗口 | 聚焦明确选中的窗口 |
| 点击右侧窗口 | 直接聚焦被点击的窗口 | 直接聚焦被点击的窗口 |
| 点击左侧应用 | 按原规则选择并聚焦该应用的最近窗口 | 按原规则选择并聚焦该应用的最近窗口 |
| 编辑搜索文本 | 更新搜索结果 | 回到应用选择状态，再更新搜索结果 |
| `Escape` | 按原规则清空搜索；搜索为空时关闭面板 | 同左侧规则，不增加额外的退出层级 |
| `Delete`／`Shift + Delete` | 按原规则发送应用级 Close Request／打开 Kill 确认 | 不执行 Close／Kill，避免把窗口高亮误解为关闭范围 |

补充规则：

- Tab 首次进入时不跳过最近窗口；再次按 Tab 才移到下一项。
- 最近窗口无法判定时，Tab 首次进入选择列表首项。这是显式窗口选择的回退，不改变原有应用级 Focus 的判定规则。
- 只有一个窗口时，Tab 与 Shift + Tab 都选择该窗口；后续循环停留在该窗口。
- Launchable App 或没有可选窗口时，Tab 不进入窗口选择，不启动应用。Enter 仍按原规则执行 Start Running。
- 窗口选择不因鼠标悬停而变化，避免干扰键盘选择。
- Close／Kill 按钮继续明确标注作用于所选应用的全部 App Window；点击按钮时仍执行应用级操作。进入 Kill 确认后，确认对话框独占快捷键处理。
- 仅处理不带额外 Ctrl／Alt／Meta 的 Tab，以及 Shift + Tab。兼容 Qt 发出的 `Key_Tab` 和 `Key_Backtab`。

例如：Ghostty 有 4 个窗口。直接按 Enter 仍聚焦最近窗口；按 Tab 进入窗口选择，再按 Tab 可以依次查看其他窗口，最后按 Enter 聚焦目标。整个过程中，上下键始终切换应用。

## 3. 视觉反馈

- 左侧保留 Selected App 的高亮。
- 右侧的「Most recent」文字继续标记最近使用的窗口。
- 应用选择状态下，右侧最近窗口保留现有默认目标提示。
- 窗口选择状态下，仅明确选中的窗口使用选中背景与边框；最近窗口仍保留文字标记。
- 窗口行增加点击光标和轻量悬停反馈，沿用 Omarchy 的颜色、边框和间距。
- 键盘选择后，将目标行滚动到可见范围。桌面事件更新列表时，保留目标附近的视图位置，替换当前每次模型变化都滚回首项的行为。
- 底部提示区按状态显示操作提示，例如应用选择时提示 `↑↓ Apps · Tab Windows · Enter Focus`，窗口选择时提示 `↑↓ Apps · Tab / Shift+Tab Windows · Enter Focus`。正式文案沿用当前界面的英文风格。
- 窄屏继续使用现有上下布局，交互规则保持一致。

## 4. 状态与实时更新

使用所选应用身份和窗口稳定 ID 表示显式窗口选择，不保存数组索引或长期持有窗口对象。当前窗口快照已有 ID，实施时沿用该 ID。

| 变化 | 处理方式 |
| --- | --- |
| 同一应用重新生成快照或列表重新排序 | 按窗口 ID 保留选择，不按旧索引选择 |
| 目标窗口更改标题或移动工作区 | 更新显示，保留选择 |
| 同一应用新增窗口 | 保留当前选择，新窗口不抢占目标 |
| 明确选中的窗口关闭 | 退出窗口选择，显示「所选窗口已不可用，请重新选择」；不自动聚焦其他窗口 |
| 所选应用消失或变为 Launchable App | 清除窗口选择，应用选择按现有规则协调 |
| 用户切换应用或编辑搜索 | 清除窗口选择，右侧重新提示新应用的最近窗口 |
| 面板关闭后重新打开 | 清除上次的窗口选择，保留现有 Previous App 初始选择规则 |

执行窗口聚焦前，必须重新从当前 Selected App 的窗口中解析目标 ID，并确认目标仍有有效句柄和精确地址。目标不存在时保持面板可用并提示错误，不能把这次指定窗口操作替换为最近窗口操作。

## 5. 实现落点

### AppDeck.qml

1. 增加显式窗口选择所需的最少状态：所选应用身份与所选窗口 ID。由当前窗口列表派生选中窗口、索引和窗口选择状态，避免多份状态失去同步。
2. 在 `handleKey` 中加入 Tab／Backtab 处理，并保留现有输入法组合状态保护和 Kill 确认优先级。上下键及其他应用导航键继续走原有应用选择流程。
3. 在打开、关闭、应用身份变化和搜索编辑时清除显式窗口选择。同一应用的实时数据更新则按 ID 协调选择。
4. 将 `focusApp` 中现有的精确窗口聚焦、确认计时器和失败恢复流程提取成可复用的窗口聚焦入口。应用级 Focus 先解析最近窗口，指定窗口 Focus 先解析显式 ID，二者复用后续流程。
5. 为窗口行增加点击处理、高亮和自动滚动。点击后立即请求聚焦，无需双击。
6. Enter 与 Focus 按钮使用一致的目标解析规则。Close／Kill 按钮保留应用级范围；窗口选择状态下拦截相应删除快捷键。

### AppDeckModel.js

仅在选择循环、ID 协调或目标查找需要独立测试时，增加小型纯函数。沿用现有窗口 ID、`mostRecentlyActiveAppWindow` 和 `focusCommand`，不引入新的窗口数据模型或后台服务。

### 输入法与失败恢复

真实键盘焦点继续保留在原生 TextInput。Tab 只改变逻辑窗口选择，并消费该按键，防止 Qt 默认焦点遍历把输入焦点转移到其他控件。用户继续输入时，退出窗口选择并正常更新搜索。

存在非空预编辑文本时，不执行窗口选择和面板快捷键，让输入法处理候选操作；保留此前针对 Fcitx5 空预编辑状态的兼容处理。窗口鼠标操作复用现有面板关闭时的输入法重置流程。

聚焦失败时，复用现有面板恢复和错误提示。若目标仍存在，保留显式窗口选择以便重试；若目标已消失，清除选择并要求重新选择。Kill 取消后恢复搜索输入能力，并保留仍有效的显式窗口选择。

## 6. 测试与验收

实施采用先补充失败用例、再实现的顺序。现有 26 项模型测试和 14 项 Qt 输入集成步骤应继续通过；以下新增测试覆盖实际行为，不仅检查函数是否存在。

### 模型与状态测试

- 首次进入选择最近窗口；最近窗口不明确时选择首项。
- 正向、反向循环；空列表、单窗口和多窗口。
- 重排、标题变化、工作区移动和新增窗口后，按 ID 保持选择。
- 目标消失、应用切换和搜索编辑后，按规则清除选择。
- 显式目标解析只接受当前 Selected App 中的窗口，拒绝陈旧目标和其他应用窗口。

### 真实 Qt 事件集成测试

扩展现有测试驱动，加载真实 AppDeck.qml，通过 Qt 键盘、鼠标和输入法事件验证：

1. Tab 首次进入、连续 Tab、Shift + Tab 和 Backtab 都选择正确窗口，真实输入焦点仍在 TextInput。
2. 窗口选择状态下，↑／↓ 和其他应用导航键仍改变应用，不移动窗口选择。
3. Enter、Focus 按钮与窗口点击选择正确目标；未进入窗口选择时仍使用最近窗口。
4. 鼠标悬停不修改选择，单击窗口只发出一次聚焦请求。
5. 编辑搜索后退出窗口选择；中文提交、预编辑和 Fcitx5 空预编辑兼容用例继续通过。
6. 窗口选择时 Delete／Shift + Delete 不发出关闭或 Kill 请求；应用选择时仍按原规则操作。
7. Close／Kill 按钮范围仍覆盖全部应用窗口，Kill 必须经过确认，确认对话框不触发窗口循环。
8. 实时列表变化与聚焦失败后，选择、搜索框和面板仍可继续操作。
9. 空搜索结果和 Launchable App 下，Tab 不进入窗口选择，Enter 的原行为不变。

聚焦请求验证应在现有外部操作边界记录真实生成的目标地址，避免测试误聚焦用户窗口；至少保留真实 Hyprland 的失败恢复测试。

### 桌面验收

- 在同一应用有多个窗口、窗口位于不同工作区时，分别用鼠标和 Tab＋Enter 聚焦指定窗口，确认目标工作区与目标窗口一致。
- 同一工作区的多个窗口也能独立选择。
- 在实际可用的多显示器环境中验证目标显示器与工作区的切换；环境不可用时记录未验证项。
- 验证中文输入、Fcitx5 候选操作、窗口列表滚动、窄屏布局和长标题显示。
- 验证目标窗口在选中后关闭、移动或被其他事件更新时，选择不跳到无关窗口。

完成 Qt 6 QML 解析、插件校验和差异检查后，再刷新已安装的 AppDeck 并检查实际效果。此方案不包含 GitHub 推送操作。
