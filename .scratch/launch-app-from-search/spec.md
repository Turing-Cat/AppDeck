# 统一软件列表与名称模糊搜索

Status: resolved
Branch: codex/launch-app-from-search

## 目标

统一展示可见已安装软件及桌面报告的 Running App，根据输入的软件名称动态模糊匹配。运行状态决定可用操作，而不是决定软件是否进入列表。

本计划已在功能分支实现。

## 列表与操作

| 软件状态 | 显示操作 | Enter 或点击软件行 |
| --- | --- | --- |
| 正在运行 | Focus、Close、Kill | Focus |
| 未运行 | Start Running | Start Running |

- 保留一个统一列表，行内显示图标、名称及运行状态；底部选中项操作区按上表显示。未运行时隐藏 Focus、Close、Kill，而非保留禁用按钮；运行中不显示 Start Running。
- 默认空输入展示全部可见已安装软件及无法关联桌面入口的 Running App。空白输入等同空输入。这是本次对未明确细节采用的默认值。
- 空查询时运行项按 Activity Order 在前，未运行项按名称在后；初始优先选中 Previous App，没有运行项时选第一个软件。
- 非空查询时所有软件按名称匹配分数统一排序，不再固定运行项优先。相同分数优先运行项，再按名称与稳定身份排序。
- 软件启动或最后一个窗口关闭后，仍作为已安装软件留在列表，更新状态和操作；既没有窗口又没有可见入口的软件才消失。
- 同名不同入口不按名称合并，必要时显示 desktop entry ID 区分。无法关联入口的 Running App 保留原有身份。
- “运行”继续表示存在对应图形应用窗口；不检查后台进程，不新增进程扫描。

## 模糊匹配规则

- 只匹配显示的软件名称，忽略大小写及首尾空白；不再用窗口标题、命令或 desktop entry ID 扩展搜索。没有桌面入口的 Running App 使用原有显示名称。
- 优先级：完全匹配 > 名称前缀 > 连续子串 > 按顺序出现的非连续字符。
- 例如 `firefox`、`fire`、`fox`、`ffx` 均匹配 Firefox，`fxf` 不匹配 Firefox。非连续字符匹配按间距更小、起点更靠前的优先。
- 空格分隔的多个词必须分别匹配同一个软件名称，综合各词得分排序；中文按实际名称字符匹配。首版不加拼音转换或编辑距离纠错。
- 每次输入变化立即筛选排序，选中排名第一的结果；随后可以上下键、翻页、Home/End 移动。
- 桌面事件刷新保留当前软件选择，包括运行与未运行之间的变化；软件退出结果集才回退到最近行。
- 无匹配显示“未找到匹配的软件”；无软件显示独立空态。

## 动作与错误处理

- Start Running、Enter、行点击共用动作分派；启动继续使用宿主应用库与当前原生接口回退，不解释搜索字符串为命令。
- 启动前刷新状态和入口：已经运行则改为 Focus，入口消失则刷新并提示不可用。
- 发出启动请求后关闭覆盖层，阻止同一次操作重复提交；同步异常恢复覆盖层、查询及可用的选择。没有成功回执时不声称窗口已出现。
- Close / Kill 的按钮与键盘入口仅用于 Running App；未运行项的 Delete / Shift+Delete 不发送请求或弹出确认框。
- Kill 保留显式确认、精确窗口所有者目标和范围复核。多个 Running App 关联同一入口时保留各运行组并省略重复启动项，不因统一列表扩大 Close / Kill 范围。
- Escape 仍先清空查询，再关闭覆盖层；详情、按钮与快捷键提示随状态更新。

## 验收

- 空查询包含运行与未运行软件；运行状态不影响非空查询的候选资格。
- 完全匹配、前缀、子串、非连续字符、多词、大小写、中文、无匹配符合上述规则；未运行软件的强匹配排在运行软件的弱匹配前。
- Firefox 运行时显示 Focus / Close / Kill，未运行时只显示 Start Running，旧的禁用按钮不出现。
- 窗口打开和关闭导致状态双向更新；已安装软件不消失，事件刷新保留选择，输入更新选中最佳结果。
- 同名入口、缺失入口、多运行组映射同一入口、入口删除不误合并、不扩大关闭范围。
- Start Running、启动前已运行、重复提交及同步异常处理正确；未运行项不能 Close / Kill。
- 运行 `node tests/model.test.js`、QML 解析、`qmllint`、`omarchy plugin validate .` 和 `git diff --check`。桌面验证覆盖两种操作区、实时输入和状态转换。
